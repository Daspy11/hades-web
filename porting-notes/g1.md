# g1: banana-ui GTK support modules

`src/banana-ui/gtk/src/Reactive/Banana/GI/{Connect,ErrorBox,Menu,Common,DataIconTheme,Table}.ts`
and the re-export module `src/banana-ui/gtk/src/Reactive/Banana/GI.ts` (ArrowDialog, Common,
Connect, Menu, Table, as in Haskell; ErrorBox and DataIconTheme are imported directly).
Demo: `src/scratch/g1Demo.ts` (`?demo=g1`).

## Connect

* `registerIOSignal(obj, sig, act)` … `registerIOSignal6`: `sig` is a toolkit signal function of
  shape `(obj, handler) => SignalHandlerId`, e.g. `Gtk.onButtonClicked`,
  `Gtk.afterTreeModelRowChanged`. `act(...args)` is synchronous and returns `[r, v]`: `r` goes
  back to the toolkit (`null` for `()`, a boolean for event signals), `v` fires the event.
  Example: `registerIOSignal(btn, Gtk.onButtonClicked, () => [null, value])`.
  Returns the `B.Event` (MomentIO is synchronous: call inside `B.compile`/`liftMomentIO`).
* `eventLink(widget, setter, event)`, `behaviorLink(widget, setter, behavior)`: `setter` is
  `(widget, a) => void`, e.g. `Gtk.labelSetText`. They stop when the widget is destroyed.
  `behaviorLink` follows *changes* only (the initial value is not pushed), as in Haskell.

## ErrorBox

* `errorBox(parent: Gtk.Widget | null, msg): Promise<void>`: modal error `MessageDialog`
  (transient for the parent's window), resolves when closed.
* `cannotHappen(err, v)` shows the box without waiting (`void errorBox`) and returns `v`.

## Menu

* `mkGtkMenu(menu: Menu<A>): [Gtk.Menu, B.Event<A>]` (MomentIO); `popupMenuOn(e: B.Event<Gtk.Menu>)`
  pops the menu up at the pointer.

## Common

* Everything synchronous except where noted. `Maybe` widget arguments/results are `X | null`
  (`widgetWindow(w): Gtk.Window | null`, `plainChanges(w | null, b)`); `safeLoadIcon(theme, name,
  size): Maybe<Gdk.Pixbuf>` keeps `Maybe`.
* `createDatePopover(prism, entry): [Gtk.Popover, Gtk.Calendar]`,
  `createColorDialog(entry): Gtk.ColorChooserDialog` (run it with `await Gtk.dialogRun`).
* `contrastText(c)`, `colourToRGBA(c): Gdk.RGBA`, `rgbaToColour(rgba)` (no monad).
* `IconData(iconName, iconPixbuf)` record; `iconThemeContents(theme, flag, pred): [Text, IconData[]][]`
  (a missing icon is skipped instead of raising a GError); `iconListWidget`, `iconTabsWidget`
  (MomentIO, return `[widget, Event<Text>]`); `iconDialog(parent, ctxs, cont)` builds and
  actuates its own network.
* `withWaitCursor(widget, () => a)`: also accepts an action returning a Promise (cursor restored
  when it settles).
* `widgetLinkColour(widget, init, colourE, colourB)`: colours any widget. Web: besides the
  canvas `draw` path of the original, the colour is applied as inline CSS whenever it changes;
  `hades-transparent-dark/-light` classes come from `Common.css`.
* `sameWidget` is reference equality; `objectDescription` uses the object id.
* `unlessFocused(w, changes, action)`, `plainChanges(w, b)`.
* `bananaCss()` is a no-op loader (the CSS is in `theme.css`).

## DataIconTheme

* `setDataIconTheme(theme)`, `getDataIconTheme()` (module-level variable, initially
  `Gtk.iconThemeNew()`).

## Table

* `mkTableView(iconTheme, flags, activationFlag, cols, initial, e, b)` →
  `[Gtk.Box, Gtk.SeqStore<Row>, B.Event<[number, Row]>, B.Event<Row[]>]`.
* `mkTreeTableView(iconTheme, activationFlag, groups, initialForest, changes)` →
  `[Gtk.Box, Gtk.ForestStore<[number, Row]>, B.Event<[Gtk.TreePath, Row]>]` (rows decorated
  with their depth, as in Haskell).
* `mkTableColumn(iconTheme, modifyModel: (path, f) => void, view, model, column)`.
* `Eq row` is structural `equals`. `item ^. fieldValue col` on a traversal combines targets with
  their monoid (text concatenation / the `Maybe` monoid).
* The colour chooser of colour cells runs asynchronously from the entry's icon-press handler.

## Toolkit changes (src/lib/GI/Gtk)

* `TreeView.startEditing`: a `CellRendererCombo` is now edited with a `Gtk.ComboBox` (as
  `gtk_cell_renderer_combo_start_editing`): renderer model, a `CellRendererText` on the
  `textColumn`, active item = the cell text; its `changed` is re-emitted by the renderer as
  `changed(path, iter)`; finishing emits `edited(path, activeText)`; closing without a choice
  cancels. New type `Gtk.CellEditable = Entry | ComboBox`, used by
  `onCellRendererEditingStarted` and `cellEditableEditingDone`; `EditingState.entry` is a
  `CellEditable`. `RenderTree.tsx` `ComboCellEditor` draws the items through the combo's own
  cell layout (icons, `cellBackgroundRgba`/`foregroundRgba` colours).
* `Render.tsx` ScrolledWindow: an explicit `minContentHeight`/`minContentWidth` now wins over a
  container's `minHeight: 0` layout (icon dialog in a notebook page was collapsing).
* `Core.ts` `widgetGetName(w)`: as `gtk_widget_get_name`, returns the GTK type name
  (`"Gtk" + capitalised kind`, e.g. `GtkLabel`) when no name was set, instead of `""`
  (`objectDescription` shows it). `w.name` itself is unchanged (still `""` by default).

## Known gaps

* GtkButtonBox children are not homogeneous (GTK gives table buttons equal widths).
* In a column holding both a pixbuf and a coloured text/combo cell, the toolkit paints the
  cell background over the whole column cell (GTK paints only the text renderer's area).
  HADES never combines `fieldIcon` and `fieldColour`.
