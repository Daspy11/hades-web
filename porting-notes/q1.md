# q1: Model.Query.Diagram

`src/hades/src/Model/Query/Diagram.ts` (tests: `Diagram.test.ts` next to it). All definitions of
`hades/src/Model/Query/Diagram.hs` are ported, exported and internal.

## Classes and dictionaries

* `Queryable<V> extends Reflective<V>`: `_QueryDiagram: Prism<V, QueryDiagram<V>>`,
  `queryAvatars(v): readonly ModelId[]`. `QueryableEntityClass<V> = EntityClass<V> & Queryable<V>`
  is the dictionary for `(EntityClass v, Queryable v)`. Pass it first.
* `Avatar_QueryElement(cls)` is the single dictionary for `Viewable`, `Connectable` and
  `Avatar HadesRender v (QueryDiagram v) (QueryElement v)`, with the `DiagramMetadataClass<null>`
  members (`DiagramMetadata (QueryElement v) = ()`, JSON `[]`). It is cached per `cls` object
  (WeakMap), so repeated calls return the same object, as `startDelta`/`DiagramWrapper` need. It is
  also exported as `Viewable_QueryElement` and `Connectable_QueryElement`. Type:
  `QueryElementClass<V>`. `HasId_QueryElement` is the `HasId` instance on its own.
* `Base (QueryElement v)` is `QueryScript v`, so in a query diagram Delta `d.base` is a
  `ModelEditCtx<V, QueryDiagram<V>>` (the script runs with `cls._QueryDiagram` as its traversal).

## Data

* `QueryData<V>`: tagged union, positional field `_0`. Constructor functions `Step(rels)`,
  `Filter(txt)`, `FilterVariants(vs)`, `SubQuery(Maybe<UUID>)`, `Variants(vs)`, `Entities(uuids)`,
  `Forwards(map)`, `Backwards(map)`, `QueryComment(txt)`; constants `Parent`, `Children`,
  `InDiagram`, `FindDiagrams`, `QueryInput`, `QueryOutput`. `def_QueryData = QueryInput`.
  Prisms are zero-arg functions: `_Step<V>()`, `_Filter()`, `_FilterVariants()`, `_SubQuery()`,
  `_Variants()`, `_Entities()`, `_Forwards()`, `_Backwards()` (and the internal `_QueryComment()`).
* `QueryBox<V>` = `{ queryBoxId, _queryBoxShape: Rectangle, _queryBoxData }`, built with
  `QueryBox(id, shape, data)`; lenses `queryBoxShape<V>()`, `queryBoxData<V>()`.
* `QueryArrow` = `{ queryArrowId, _queryArrowShape: LineShape }`, `QueryArrow(id, shape)`;
  lens `queryArrowShape` is a constant.
* `QueryElement<V>` = `QElemBox(_0: QueryBox)` | `QElemArrow(_0: QueryArrow)`; prisms
  `_QElemBox<V>()`, `_QElemArrow<V>()` (exported, though Haskell does not export them).
* `QueryDiagram<V>` = `{ _queryDiagram: DiagramEntity<QueryElement<V>, null>, _queryInputs:
  S.Set<Variant<V>>, _queryDescription }`, `QueryDiagram(d, inputs, desc)`; lenses
  `queryDiagram<V>()`, `queryInputs<V>()` (`queryDescription` is commented out, as in Haskell).
* `ViewContext (QueryElement v)` is `QueryContext` = `{ queryContextId }`, `QueryContext(id)`.
* `QueryScript<V, A> = ModelScript<HadesRender, V, A>` (extra result type parameter).

## JSON / Reflective

* Constants `JSON_QueryBox`, `JSON_QueryArrow` (with the "bogus zero-length arrow" fix-up on read),
  `JSON_QueryElement`. Function `JSON_QueryDiagram(cls)` (reads both the current
  `{diagram, inputs, description}` form and v0.5 plain diagrams). Output matches aeson; all query
  diagrams in `src/dsm/share/examples/*.dsm` round-trip exactly (tested).
* `Reflective_QueryDiagram(cls)`. **Laziness:** its `reflectiveDefaults` is a memoised getter and
  the default query's `_queryInputs` (all variant names of `v`) is a memoised getter computed on
  first read. So a model type whose `reflectiveDefaults` include the query default (e.g.
  `map BasicQuery reflectiveDefaults` in `Model.Abstract.BasicTypes`) can build them without
  infinite recursion, as long as it does not *read* `_queryInputs` of that default while building
  `cls.reflectiveDefaults`. Do not spread `Reflective_QueryDiagram(cls)` into another object at
  dictionary-construction time (spreading evaluates the getter); delegate to it instead
  (`get reflectiveDefaults() { ... Reflective_QueryDiagram(cls).reflectiveDefaults ... }`).

## Functions (dictionary first, then context, then Haskell arguments)

* `compileQueryDiagram(cls, model, diagramEntity): Either<string[], Query<V>>` (pure; run with
  `runQuery(q, outers, model, inputs)` from `Model/Query/Base`).
* `queryDiagramWrapper(cls, ctx: ModelEditCtx<V, QueryDiagram<V>>, ent): Maybe<EntityWrapper>` —
  a `ModelEdit`; from a `HasDiagrams.getDiagramWrapper(ctx, e)` use
  `withSubtype(ctx, cls._QueryDiagram, (c) => queryDiagramWrapper(cls, c, e))`.
* `queryActivation(cls: HasDiagrams<HadesRender, V> & Queryable<V>, ctx, ent)` — a `ModelScript`
  generator at `W = QueryDiagram<V>`; as an `ActivationScript`:
  `promoteScript(cls._QueryDiagram, (c) => queryActivation(cls, c, ent))`.
* `queryBackgroundMenu(cls)` → `(p) => Menu<Action<QueryElement<V>>>`; `queryBackgroundMenu(cls, p)`
  → the menu.
* `queryElementDialog(cls)` → `DialogSelector_<Model<V>, null, QueryElement<V>>`.
* `chooseQueryDialog(cls)` → `Dialog_<Model<V>, null, S.Set<UUID>>` (single-entity `refPicker` of
  query diagrams).
* `queryDiagramToolbar(cls)` → `DeltaToolbar<QueryElement<V>>`.
* `queryForest(cls, model)` → `Forest<readonly [string, Maybe<string>, Maybe<ModelId>]>`.
* `queryTest(cls, qd)` → `DialogSelector_<Model<V>, null, null>` (call `(model, null)`).
* `clickableEntitySet(cls: Editable<P, V> & EntityClass<V>)` →
  `Gadget_<Model<V>, ModelScriptAct<P, V, V, Maybe<string>>, S.Set<ModelId>>`.

## Notes

* No toolkit changes. No async code (dialogs go through script instructions).
* `Diagram.test.ts` has a reusable toy `Queryable`/`HasDiagrams` model and an `Editor` harness
  that drives a query diagram Delta inside model scripts on the `_QueryDiagram` subtype
  (toolbar box/arrow tools, "Edit inputs", "Test query", box descriptions rendered to SVG).
* Known gap: none. Errors thrown from the Delta (e.g. `throwUser("Query has been deleted.")`) are
  `ModelErrorException`s, as with other ModelEdit errors.
