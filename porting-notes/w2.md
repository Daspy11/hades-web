## API (conventions of `Network/Webits`, porting-notes/w1.md)

`Elmer` functions take the `ElmerEnv` first. In this module the Haskell code calls the gadget
environment `env`, so the `ElmerEnv` parameter is named `elmer`. Everything is synchronous
(network building, like Haskell's `Elmer` before the daemons run); the daemons are async loops.

* `renderGadget(elmer, env: TState<boolean, E>, i: TState<boolean, GadgetData<I>>, g: Gadget<E, W, I, O>): GadgetOut<W, O>`
* `createDialog(elmer, env, [key, initial, dialog]): [WebitContainer, TChan<[K, Maybe<A>]>]` — shows a
  jQuery UI dialog at once (the `form` webit is a child of `elmerTop`).
* `mkWebitPopupSelect(elmer, env, selector: DialogSelector_<E, W, A>, trigger: STM<readonly [K, A]>): TChan<[K, Maybe<A>]>`
  (`trigger` is an STM thunk that retries until a popup is wanted, e.g. `() => readTChan(chan)`).
* `GadgetOut<W, O>` record `{ gadgetView: WebitItem[], gadgetDomCode: RemoteMonad<null>,
  gadgetEvents: STM<W>, gadgetOutput: TState<boolean, GadgetData<O>> }`, constructor `GadgetOut(...)`,
  instances `fmap_GadgetOut`, `pure_GadgetOut`, `ap_GadgetOut`, plus `liftA2_GadgetOut`. After
  showing `gadgetView`, send `gadgetDomCode` with `send(env.elmerEngine, out.gadgetDomCode)` (tables
  and display popups need it).
* Also exported (internal in Haskell): `cleanOutput(elmer, st)`, `qualifyOutput(ok, o)`,
  `mergeGadgetData(ts1, ts2)`, `makeTab(elmer, env, i, header, container, [label, g])`,
  `FTSelection`/`show_FTSelection`/`FromJSON_FTSelection`, `TreeMoveMode` (+ `treeMoveModeValues`,
  `FromJSON_TreeMoveMode`).
* `FancyTreeIcon` (`FtIconNone`, `FtIconDefault`, `FtIcon(t)`), `FancyTree` record +
  `ftDefault(key, title)`, `ToJSON_FancyTreeIcon`, `ToJSON_FancyTree` (fields left out as aeson's
  instance does). `showOpr(f, op)`.
* `arrowDialogPrelude()` is a function (the `unsafePerformIO` constant). As in Haskell it reads the
  data file `arrowDialog.js` (without the `JS/` directory) and therefore throws "does not exist";
  `elmerScotty` loads `JS/arrowDialog.js` itself.

Table:

* `mkTableWebit(env, editFlags, spec, initial): [Webit<readonly Row[]>, RemoteMonad<null>]`,
  `mkTableWebitWithClicks(env, editFlags, spec, initial): [Webit, RemoteMonad<null>, TChan<number>]`
  — send the `RemoteMonad` once the webit is in the DOM (AppendGrid needs the element).
* `fieldToColumn(wId, clickFlag, grid, colNum, tf)` → `[JavaScript, (row) => J.Value, (j) => (row) => row]`
  (the setter stays curried, it is partially applied). `jsSendChange`, `updateDecorations`,
  `columnId`, `nullIsNothing(prism)`, `tableIcon`, `applyTableRowOp(Maybe default, op, xs)`,
  `deleteTableWebit(env, wt)` (async), `WebitTable`, `TableIconClick` (+ `show_`, `FromJSON_`),
  `TableRowOp` = `TableRowInsert(n)` | `TableRowDelete(n)` | `TableRowSwap(n)` (+ `FromJSON_TableRowOp`).
* AppendGrid is the bundled UMD build (global `AppendGrid`, loaded by `elmerScotty`).

## Representation choices

* `proc` blocks (general `Optional`) are desugared with `gPipe`/`gFirst`/`arr`.
* `Loop` (`mdo`): the loop input reads the body's output through a lazy `TState` that throws
  "cyclic evaluation in fixIO" when it is used while the body is still being rendered — as the
  Haskell `fixIO` does. So, as in the original, a `loop` whose body reads its input at render time
  (any editor) fails; only lazy bodies (`arr`, `pure`) work. Webits code in HADES never uses `loop`.
* `Intercept` (`mdo`): the Haskell puts the container's own id in the attribute of the container
  it is creating, which forces the fixIO result (FixIOException in the original). The port sets the
  attribute right after creating the container (`// Web:`); as in Haskell the box is never shown.
* `Exec`: `deleteWebit` is async, so re-rendering after an argument change awaits it.
* `LT.decodeLatin1 . encode` (JSON spliced into JavaScript) is reproduced: non-ASCII text arrives
  as its UTF-8 bytes read as Latin-1, as in the original.
* JSON parsers for channels are `J.FromJSON` dictionaries passed to `addWebitChannel`.
* Laziness kept where it changes what fails: `FromJSON_FTSelection` accepts any key string and
  throws "Prelude.read: no parse" only when `ftsKey` is read (a getter); the row of a click in a
  table with a row dialog (`v !! row`) is a getter too, so a click on a row the table does not have
  yet is consumed and the popup daemon fails after its transaction (and restarts), as in Haskell.

## Faithful quirks of the original (reproduced; marked "Faithful:" in the code)

* `box`, `grid`, `tabForm` and `validateText` return their children's views, not their own
  container: no tab bar, no grid, no separators, no warning text. `grid` uses `tc` cells that are
  never attached.
* Tab buttons of `unionTab` all keep the `active` class from creation (`webitIn btn ()` never sends
  anything because `() == ()` in `makeWebit`); `openTab` gets the event instead of the button.
* `validate` adds the CSS class `invalid` when the value is *valid*.
* `validate`/`validateText`: the style daemon reads the same (non-duplicated) event streams as the
  output, so it usually consumes the inner gadget's edits before the dialog sees them: an invalid
  edit does not disable OK (the behaviour, read on OK, still has the edited value).
* Display gadgets and two editors focused on the same field overwrite each other's edits inside a
  `form`/`box`/`grid`/`tabForm` (earlier rows are applied last), as in the GTK interpreter
  (porting-notes/g2.md). `readOnlyText`/`readOnlyMemo` (no selector) never update their text.
* `enabled` pushes `setAttribute(disabled,disabled)` with an undefined variable (console error on
  every input event; the fieldset is only disabled at creation). `frame` never updates its
  `current` label and its label JavaScript lacks a dot. The `Optional DateBox` handler never sends.
* Forest editor: "Add after" on the root sends JavaScript with an extra brace; replacing the whole
  forest from the application calls `reload` on a selector string. Node labels in the demo read
  "(Y" because of the original's operator precedence.
* Table: an icon chosen from the icon menu is first written into row number *column number*
  (corrected by the edit event that follows); edits of `EditEnum` and `Opt EditBool` columns are
  ignored (the browser reports a `select` value as a string); the icon `onclick` of a table opened
  with clicks is broken (nested `jsb.event`).
* The webits standard CSS `.horizontal > *` rule is dropped by the browser (blaze escaping, w1), so
  horizontal boxes/button bars stack vertically.
