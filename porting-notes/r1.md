* `ImageRef`: `IconRef(name)` | `DiagramRef(modelId)`, **always build with the constructors** (they

## Model.Report.Docx (Word output)

* `makeDocx(fmt: Maybe<ReportPageLayout>, title, target, blocks, imageMap): Promise<void>` and
  `insertDocx(template, target, blocks, imageMap): Promise<void>`. `imageMap: ImageFiles` =
  `M.Map<ImageRef, readonly [Uint8Array /* PNG */, Maybe<Uint8Array> /* SVG */]>` (Export.hs's
  `ImageMap`). Targets are `@/lib/System/IO` virtual paths (`/download/<name>` downloads, a
  `/handle/...` path from the save picker writes in place, `/memory/...` keeps it); ".docx" is
  appended when missing; the bytes are written with `writeFileData(path, bytes, docxMimeType)`.
  The template is read with `readFileBytes`.
* Also exported: `blockToDocx(st, level, style, blk)`, `listItem`, `inlinesToDocx`, `inlineToDocx`,
  `attrRun`, `attrBookmark`, `matrixToDocx`, `addImages`, `modifyDocumentAttrs`, `appendBodyElements`,
  `isNamedElem`, `requiredNamespaces`, `ignorableNamespaces`, `iconSize`, `ListType`.
* `Docx/Document`: `DocMonad = StateCell<DocState>` passed first (`newId(st)`, `addMedia(st, ref, typ,
  targetType)`, `getMediaRef(st, ref, targetType): Maybe<Relationship>`, `addExternal(st, url)`,
  `bookmark(st, nm, es)`, `linkExternal(st, url, es)`); start with `{ state: docStart }`.
  **`RelTargetType` = `"PngTarget" | "SvgTarget" | "ExternalTarget"`** (Export.hs's
  `binaryResourceFunc iconTheme ref PngTarget` → `"PngTarget"`). `(X.Node t) => t` arguments are
  `X.NodeArg` values (`null` for `()`, a pair `[attrs, contents]`, …). `tShow` accepts numbers, strings,
  booleans.
* `Docx/Drawing`: `EMU = number`; `inlinePicture(st, [w, h], ref, title)`.
* `Docx/File`: the skeleton `share/docx` is bundled with `import.meta.glob(..., { query: "?raw",
  exhaustive: true })`, so `getSkeletonStyles(names): X.Element[]` and `walkDirectory` are synchronous
  and work in tests; `getSkeletonDir()` = `/src/hades/share/docx`. `writeDocxFile(title, target, edits,
  additions)` and `insertDocxFile(template, target, edits, additions)` are async; `renderXml(cs)`,
  `updateXml(f, bytes)`, `setCreation`, `setModified`, `namedBlankStyle`, `docxMimeType`, `findNameDF`
  (re-export), and `isExtensionOf(ext, path)`: an exact port of `System.FilePath.isExtensionOf`
  (case-sensitive, on `takeExtensions`), used for the ".docx" suffix check instead of the
  case-insensitive `@/lib/System/IO` version (so `Report.DOCX` becomes `Report.DOCX.docx`, as in
  Haskell). Zip via fflate (entries in path order, DOS times = UTC fields as zip-archive). The
  creator/last-modified name is `System.Hades.DataFiles.getUserName()` (`// Web:` no `USER`/`USERNAME`).
* Output checked with Python (`zipfile` + ElementTree: well-formed parts, content types, relationship
  targets, relationship ids, styles) and `python-docx` for makeDocx/insertDocx output, both in vitest and
  for a document generated in Chrome by the demo.

## Faithfully kept quirks of the original

* `insertDocx`: template parts that are edited (`document.xml`, `styles.xml`, `core.xml`, rels, content
  types) are parsed from bytes as Latin-1 and written with numeric references, so non-ASCII *template*
  text becomes mojibake (`Café` → `Caf&#195;&#169;`); inserted report text is correct. Fix (one line):
  `X.parseXML(U.decodeUtf8(bytes))` in `Docx/File.updateXml`. For the same reason a template part
  that starts with a UTF-8 byte order mark comes out with `&#239;&#187;&#191;` before its XML
  declaration, which makes it ill-formed (the same fix removes it; `TextDecoder` drops the BOM).
  The skeleton's own `styles.xml` has a BOM but `makeDocx` copies it unedited, so it is unaffected.
* Report text: joining result fragments adds a `Space` before following inlines / the next paragraph,
  and an empty `Para []` before a following non-paragraph block (e.g. between two sub-report headings):
  HTML drops it, Word shows an empty paragraph.
* A decorated Boolean that is true is highlighted with the *false* colour.
* Word: every numbered list item restarts `LISTNUM` (`\s 1`); matrix cells use the matrix class as
  paragraph style; `Span` makes a run inside a run; `makeDocx` adds no styles for custom classes.

## Testing notes

* jsdom's `Blob` has no `arrayBuffer`, so `readFileBytes` of a `/memory/` file fails in vitest. The tests
  replace `writeFileData`/`readFileBytes` with `vi.mock("@/lib/System/IO", ...)` (see `Docx.test.ts`).
* fflate decides "file or folder" with `instanceof Uint8Array` of its own realm; TextEncoder output is from
  another realm under jsdom. `Docx/File` copies bytes into fflate's realm (`zipSync({}).constructor`).
* `DocxCheck.ts` (`checkDocxFile(path)`) is reusable for Export tests.

No toolkit (`src/lib/GI`) changes.
