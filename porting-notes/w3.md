Files (every definition of the Haskell modules ported, Haddock kept as TSDoc):

| Haskell (`banana-ui/webits/demo-webit/`) | TypeScript (`src/banana-ui/webits/demo-webit/`) |
|------------------------------------------|-------------------------------------------------|
| `Types.hs`                               | `Types.ts` (+ `Types.test.ts`, 7 tests)         |
| `Menu.hs`                                | `Menu.ts`                                       |
| `Dialog.hs`                              | `Dialog.ts` (+ `Dialog.test.ts`, 5 tests)       |
| `Matrix.hs`                              | `Matrix.ts` (+ `Matrix.test.ts`, 4 tests, one drives `demoMatrixAction` in jsdom) |
| `Main.hs`                                | `Main.ts` (+ `Main.test.ts`, 9 tests: front page → demo dialog → OK → log, forest editor dialog, clickable image) |

Run it with `http://localhost:5173/?demo-webit` (`src/main.ts` calls `main()`). Scratch demo
`src/scratch/w3Demo.ts` (`?demo=w3`) runs the same `main` with test conveniences:
`&seed=<n>` (reproducible random data), `&open=dialog|matrix|menu|forest|image` (clicks that front
page button), `&icons=diametric` (also registers the Diametric icons, see below), `&log=1` (console
output in a side panel; `window.w3.log`).

## New library: `src/lib/Test/QuickCheck.ts` (+ test, 14 tests)

The generator half of QuickCheck 2.14 (no property runner; tests use vitest). Use it wherever a
Haskell module builds random data with `Gen`/`Arbitrary`.

* `Gen<A> = (r: QCGen, size: number) => A` (`MkGen`); direct style:
  `do x <- g1; y <- g2; return (f x y)` → `(r, n) => { const x = g1(r, n); const y = g2(r, n); return f(x, y); }`.
  `fmap_Gen`, `pure_Gen`, `ap_Gen`, `bind_Gen`, `unGen(g, r, n)`.
* `generate(g)` is synchronous (fresh seed, size 30); `generateWith(seed, size, g)` and
  `setQCGenSeed(seed | null)` (web/test only) make it reproducible. `sample_(g)`.
* Combinators: `sized`, `getSize`, `resize(n, g)`, `scale`, `choose([lo, hi])` (integral; also
  `chooseInt`, `chooseInteger`), `chooseDouble`, `chooseEnum(values, [lo, hi])`, `suchThat`,
  `suchThatMaybe`, `oneof`, `frequency`, `elements`, `sublistOf`, `shuffle`, `listOf`, `listOf1`,
  `vectorOf(n, g)`, `vector(cls, n)`.
* `Arbitrary<A>` dictionary (`arbitrary`, `shrink`); instances `Arbitrary_Bool`, `_Int`,
  `_Integer`, `_Double` (2.14's mixture), `_Word8` (`arbitrarySizedBoundedIntegral`), `_Char`,
  `_Unit`, and `Arbitrary_List(cls)`, `_Maybe(cls)`, `_Set(cls)`, `_Tuple2(c1, c2)`,
  `_Tree(cls)` (2.14's size partitioning), `_Forest(cls)`. Helpers `arbitrarySizedIntegral`,
  `arbitrarySizedNatural`, `arbitrarySizedFractional`, `arbitraryBoundedIntegral`,
  `arbitraryBoundedEnum(values)`, `shrinkNothing`, `shrinkIntegral`, `shrinkDecimal`,
  `shrinkList` (checked against the Haskell definitions in the test).

## API / representation

* Types: `DemoEnum` string enum (`demoEnumValues`, `show_/read_/compare_DemoEnum`,
  `Arbitrary_DemoEnum`); records `DemoTable(...)`, `DemoData(...)` with the Haskell field names,
  derived `show_DemoTable`, `show_DemoData` (exact Haskell text, tested); constant lenses
  `boolField` … `demoTable`; `demoDefault`, `prettyDemo`, `demoForest`; generators
  `arbitraryColour`, `arbitraryDay`, `arbitraryIcon` (`QC.Gen`), `arbitraryText(n)`;
  `Arbitrary_DemoTable`, `Arbitrary_DemoData`.
* `iconList`, `wordsList` (Haskell `unsafePerformIO` CAFs on the author's home directory) are module
  constants. Web: `iconList` reads the bundled DSM Diametric theme
  (`getDataDir("dsm")/Diametric/{scalable,48x48}`), `wordsList` the webits data file `words.txt`
  (`?raw` import; identical to the original's file).
* Gadgets/dialogs polymorphic in `w` are constants typed `any` for `w` (`demoDialog`,
  `demoTableForm`, `demoSetPopup`, `demoForestSelection`, `matrixColumns`, `demoForestEditor`).
  `loremIpsum` and `demoSetPopup` are defined before their users (TS constants are strict).
* Elmer actions take the `ElmerEnv` first: `demoMenuButton(env): WebitItem`,
  `choiceButton(env, display): Webit<Text>`, `demoImageAction(env): void`,
  `demoMatrixAction(env, modelState, modelWriter, keys): Promise<void>` (never resolves: `forever`),
  `choicePage(env, modelState, modelWriter, matrix): Promise<void>`. The model writer is the STM
  action `(b, m) => void`. `Model = M.Map<number, DemoData>`, `MatrixItems`.
* `arbitraryMatrix(n): QC.Gen<[Model, MatrixItems]>`, `demoMatrix(keys)`, `defaultIso(d)` (Eq is
  structural `equals`).
* `proc` block of `demoDialog` desugared GHC-style with `arr`/`gFirst`/`gPipe` (original kept in a
  comment). `join $ atomically (a `orElse` b `orElse` c `orElse` d)` returns an `Elmer<void>` run
  with `await next(env)`. `traceM` → `console.debug`, `putStrLn` → `console.log`.

## Web restructurings (`// Web:` in the code)

* Server start-up: `main` prints the page URL instead of `http://localhost:3000/`, registers the
  icons with `elmerStatic`, registers the program's own Scotty routes in a local table (`get
  "/image.jpg"` → the bundled `Testcard_F.jpg`, logging `GET image: fn = ...`; `notFound` logs
  `Scotty 404: ...`), then mounts the page with `elmerScotty`. `scottyUrl(url)` (exported) resolves a
  page URL through those routes, then `elmerStaticUrl`; `demoImageAction` uses
  `image(scottyUrl("image.jpg"))` because a relative `image.jpg` does not reach a route here.
* Icons: `/usr/share/icons/Adwaita/scalable` → the toolkit's bundled Adwaita icons
  (`/src/lib/GI/Gtk/icons`, one group "Adwaita"); no 48x48 Adwaita set is bundled (`icons2 = []`).

## Faithful behaviour of the original (checked in the browser)

* Each front page button is its own `div` webit, so the buttons stack vertically. Clicking a demo
  button (except "Clickable Image Demo") deletes the button box; `choicePage` handles one click only
  ("Matrix Demo" never returns; after the image demo the other buttons are dead).
* Broken images: the demo data names icons of the author's own icon set (`basic_checked`,
  `computer-about`, `general-car`, `emoji-happy-1`, `computer-add`, ...), and the random matrix data
  uses Diametric names, while the program serves only Adwaita icons, so those `<img>`s are broken
  as in the original. `?demo=w3&icons=diametric` registers the Diametric icons too (random icons
  then show).
* Forest editor labels read "text (Y" / "text (N)" (operator precedence in `demoLabel`).
* Random data differs on every load (QuickCheck `generate`); `resize 5` forests may be empty.

## Known gaps

* `@/lib/Data/Tree` `drawTree`/`drawForest` omit the trailing newlines of Haskell's `unlines` (and
  split labels on every newline rather than with `lines`). Other modules' tests depend on the
  current output, so the lib is left alone; `Main.ts` has (and exports) a local `drawForest`
  that matches containers' `Data.Tree.drawForest` exactly, so the "Forest edit output" log ends
  with its blank line as in the original (tested in `Main.test.ts`).
* `elmerLog` locations come from the JavaScript stack (`Main.elmerLog:<line>`), not Haskell's
  `HasCallStack` (w1).
