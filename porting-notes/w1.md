## How the "server" runs in the page

* The Haskell side and its browser client are the same page. `start(app)` (from
  `@/lib/Network/JavaScript`) creates the loopback engine, installs the client half of the bridge
  as the global `jsb` (`jsb.rs`, `jsb.event`, `jsb.reply`, `jsb.error`, exactly the 0.2.0
  bootstrap) and calls `app(engine)`.
* `send(eng, m)` is **synchronous**: each `command`/`constructor`/`procedure` is evaluated as it
  is reached with `new Function(js)` (global scope). A failing command is logged and the rest of
  that `send` is skipped, as in the original packet `eval`. A failing `procedure` throws
  `JavaScriptException`.
* Pushed JavaScript therefore only sees **globals**: jQuery (`$`), jQuery UI, Fancytree,
  `AppendGrid` (UMD build, global) and the functions of `JS/arrowDialog.js` (`fancyToTree`,
  `fancyToForest`, `openTab`, `ancestorZ`, `legalDrop`). (In the original page `AppendGrid` was a
  module import reachable through a direct `eval`; here it is a global, same name.)
* `jsb.event(v)` (from inline handlers such as `onclick`) writes into the engine's event `TChan`;
  the command-pipe thread of `makeElmerEnv` routes it to `elmerRoutes` as before. With
  `jsb.debug = true` (set by `elmerScotty`, as the original page did) every evaluated statement and
  event is echoed to the console (`eval ...`, `event ...`), as in the original.
* JavaScript text is a `string` (`JavaScript` newtype erased): `<>` is `+`, `mconcat` is
  `.join("")`. `var rv` is `var_(rv)`; `value x` takes a `J.Value` (numbers, strings, booleans,
  arrays work directly; other types: `value(JSON_X.toJSON(x))`); `call(fn, args)`; `RemoteValue<A>`
  is `{ _0: n }`. Remote monad: `RemoteMonad<A> = (f) => A`;
  `do { rv <- constructor js; command c; return rv }` →
  `send(eng, (f) => { const rv = constructor<Html>(js)(f); command(c)(f); return rv; })`;
  `seqRemote(m1, m2, ...)` for `>>`/`mapM_`; `JS.delete` is `delete_` (also `delete`).

## Monads, STM and threads

* `Elmer a` (`ReaderT ElmerEnv IO`) → explicit `env: ElmerEnv` parameter after the dictionaries:
  `showWebit(cls, env, container, w)`. A first-class `Elmer a` (argument of `runElmer`,
  `forkElmer`, `elmerDaemon`, finalisers, the IORefs in `webitFinal`) is
  `Elmer<A> = (env: ElmerEnv) => A | Promise<A>`. `ask` is `env`, `asks f` is `env.f`.
  Async (return Promises): `runElmer`, `makeElmerEnv`, `elmerScotty`, `getIconChoice`,
  `deleteWebit`, `webitFinalise` (class method). Everything else is synchronous.
* `STM a` → a thunk `() => A`; STM primitives work inside a transaction and also on their own
  (they then commit at once). `liftIO $ atomically act`: `await atomically(() => ...)` if it may
  `retry` (block), `atomicallySync(() => ...)` if it never retries. `orElse(a, b)` takes thunks,
  `retry()`, `check(b)`, `throwSTM(e)`.
  The common `join $ atomically (... return ioAction)` → `const io = await atomically(() => { ...;
  return () => ... }); await io();`.
* `forkIO $ forever $ ...` → `forkIO(() => forever(async () => { ... }))`. `killThread` can only
  interrupt a blocking call made in the **synchronous part** of a loop iteration, so put the
  `await atomically(...)` that waits for input first in daemon bodies (as the Haskell code does).
  A thread killing itself does not throw at once; it stops at its next blocking point.
* `elmerDaemon(cls, env, owner, action)`: `action` is an `Elmer<void>` run `forever`; restart
  after 1 s on `ElmerException`/`ErrorCall` (JS runtime errors count as `ErrorCall`); killed by
  the owner's finaliser. Log messages as in Haskell.
* `MonadFix Elmer` / `mdo` (ArrowDialog `Loop`, `Intercept`): no direct counterpart; use a
  mutable cell or a thunk filled in after the later binding.
* `HasCallStack` is dropped; `elmerLog` takes its location from the JS stack for `logLine`.

## Data and classes

* `WebitClass<A>` dictionary: `webitHandle`, `webitId`, `webitParent`, `webitChildren` (STM),
  `webitFinalise(env, a): Promise<void>`, `webitAddFinaliser(env, a, act)`. Instances
  `WebitClass_WebitItem`, `WebitClass_WebitContainer`, `WebitClass_WebStatic`, `WebitClass_Webit`,
  `WebitClass_WebitMenu` (in `Webits/Menu`).
* `WebitItem` existential: `WebitItem(cls, w)` (`{ _cls, _0 }`); `webitTree(item)` (STM).
* Records keep their Haskell fields: `WebitContainer(handle, id, parentTVar, childrenTVar,
  finalIORef)`, `WebStatic(...)`, `Webit(webitHandle1, webitIn, webitState, _webitCurrent,
  webitId1, webitParent1, webitFinal)` — the `Webit` constructor is exported (Table builds one).
  `webitIn: (a: A) => void` is an STM action; `webitState: TState<null, A>`.
* `ElmerEnv` fields as in Haskell (`elmerIds` is a `TVar<Iterator<UUID>>`, `elmerRoutes` a
  `TVar<M.Map<WebitId, ((v: J.Value) => boolean)[]>>`). `elmerIconMenu` is a lazy getter
  (non-strict in Haskell); `{ ...env, elmerZ: z }` works on a finished env.
* JSON constraints are codecs, passed first: `makeWebit(codec, env, fragment, inputF, initial)`
  with `inputF: (a, rv, wId) => JavaScript` (uncurried); `addWebitChannel(fromJ, cls, env, w)`;
  `addWebitChannelWith(cls, env, parser, w)`; `webitEvent(toJ, wId, v)` (`()` is
  `webitEvent(J.unitJ, wId, null)`); `setAttribute(cls, toJ, item, attr, val)`;
  `deleteAttribute(cls, item, attr)`, `addClass(cls, item, nm)`, `removeClass(cls, item, nm)`.
* Unchanged helpers: `jsNoOp`, `htmlValue(h)`, `jsValue(js)` (escaped attribute value),
  `webitSelector(wId)`, `webitSelector1(wId, suf)`, `webitEventData(wId, js)`,
  `setWebitHtml(html, rv)`, `flushTChan(c)`, `newWebitId(env)`, `makeWebitContainer(env, cls)`,
  `makeWebitContainer1(env, tag, [[attr, val], ...])`, `makeWebStatic(env, html)`,
  `showWebit`, `hideWebit`, `deleteWebit` (async), `iconPic(wId, nm)`, `iconHtml(sty, nm, Maybe wId)`,
  `getIconChoice(env, initial)` (async).
* Logging: `Priority` string enum + `priorityValues`; `LogItem`, `logLine`, `show_LogItem`,
  `logToStderr(env)` (browser console), `elmerLog(env, pri, msg)`, `elmerLogSTM(env, pri, msg)`,
  `elmerLogIO(...)`.
* `show_Value(v)`: Haskell `show` of an aeson `Value` (`Object (fromList [("d",String "...")])`),
  used in the `ElmerDecodeError` message and the "Elmer event received" trace.
* `TState<A, B>` record of STM thunks `{ tStateBehaviour, tStateEvent, tStateDup }`; constructor
  `TState(b, e, d)`; instances `fmap_TState(f, ts)`, `pure_TState(v)`, `ap_TState(tf, tv)`,
  `liftA2_TState(f, x, y)`. `newTState(x)` (STM) / `newTStateIO(x)` return
  `[ts, writer]` with `writer(a, b)` an STM action. `tStateDupIO`, `mapTState1(f, ts)`,
  `filterTStateMaybe(d, ts)`, `filterTStateChanges(ts)`, `unionTStates(initial, list)` are
  synchronous and fork their threads.
* `Data.ForestModel` (import as `FM`): `Edit<A, B> = (st: StateCell<Model<A>>) => B`;
  `FM.runEdit(act, m)` → `[b, m']`, `evalEdit`, `execEdit`; Edit functions take `st` first:
  `FM.runEdit (FM.insert FM.InsertBefore idx v) m` → `FM.runEdit((st) => FM.insert(st,
  "InsertBefore", idx, v), m)`. `Insertion` string enum + `insertionValues`. `modelIso<A>()`
  is a function (`m ^. from FM.modelIso` → `view(from(FM.modelIso()), m)`); `emptyModel()` is a
  function; `Model` is a class with the Haskell `Eq` (`[EqSym]`, `eq_Model`); `ix_Model(k)` is the
  `Ixed` instance, `fmap_Model` the Functor; `FM.delete_` (also `FM.delete`), `move(st, i, ins,
  target)`, `mapWithIndex((i, a) => b, m)`, `stableUpdate(forest, m)`. Partial functions throw.

## Icons, static files, page

* `IconGroup(name, M.Map<IconName, IconData>)`, `IconData(path, "IconSvg" | "IconPng")`,
  `show_IconMime`. `getIconData(virtualDir)` is **synchronous** and reads the bundled icon files
  (`/src/lib/GI/Gtk/icons/...`, `/src/hades/share/...`, `/src/dsm/share/...`, `/src/banana-ui/...`),
  e.g. `getIconData("/src/hades/share/hicolor/48x48")` → groups Actions, Categories, Stock.
  As in Haskell only files directly inside each group directory count, so that "Stock" group is
  empty (its icons are in `stock/image/`; `getIconData(".../48x48/stock")` gives group "Image").
  `mergeIconGroups`, `allIcons`.
* `scottyIcons(groups)` / `elmerStatic(groups)` register the icons page-wide and set the favicon.
  `iconUrl(nm)` = bundled file URL + `#/icons/<nm>` (the last path component is still the name, so
  `iconFromUrl` and `this.src.substring(this.src.lastIndexOf('/')+1)` keep working);
  unregistered icons give `/icons/<nm>` (broken, as the original server's 404). `iconIso`.
* `elmerScotty(route, htmlHead, icons, action, container = document.body)`: injects `htmlHead`,
  jQuery + jQuery UI (theme CSS via Vite import), Fancytree 2.38 + skin-win8, AppendGrid,
  `JS/arrowDialog.js` and `standardHeader`, sets `jsb.debug`, appends the original's `<noscript>`
  message and `<div id="main">` to `container` and runs `action` on a fresh env. It never resolves if `action` never returns.
* `elmerStaticUrl(url)` (web-only): resolves the original static routes (`/favicon.ico`,
  `/icons/:icon`, `/assets/<data file>` with the optional `.js` suffix, also relative
  `assets/...`) to bundled URLs; applied to `src`/`href` in `htmlHead`. App-specific routes (the
  demo's `/image.jpg` → `Testcard_F.jpg`) need `getDataFileName("webits", ...)` in the app port.
* Vendored client assets under `src/banana-ui/webits/`: `JQuery/` (jQuery 3.6.0 + jQuery UI 1.13.0
  with its theme), `JS/AppendGrid.js` (UMD) and `JS/lib/` (module sources), `JS/arrowDialog.js`,
  `JS/fancytree/` (**new**: jquery.fancytree 2.38.5 `jquery.fancytree-all.min.js`, `skin-win8/`,
  MIT licence; replaces the original's jsDelivr links so the page works offline and in tests).

## Blaze (`import * as H from "@/lib/Text/Blaze/Html5"`, `import * as HA from ".../Html5/Attributes"`)

* Elements take children: `H.div $ do a; b` → `H.div(a, b)`; a string child is escaped text;
  leaves take none: `H.img()`. `H.p` exists (as `p_` too), `H.var_`.
* `!` → `H.with_(h, attr1, attr2)` (attributes rendered in source order, applied to every
  top-level element). `H.with_` on an element *function* returns a function, as blaze's
  `Attributable` for functions: `(H.th ! HA.rowspan "2") . H.text` →
  `(t) => H.with_(H.th, HA.rowspan("2"))(H.text(t))`. `!?` → `H.withIf(h, [cond, attr])`.
* `do`-blocks/`mapM_`/`mconcat` → `H.mconcat_Html([...])`; `return ()`/`mempty` → `H.mempty_Html`.
* `H.text`/`H.string`/`H.lazyText` escape (`& < > " '`), `H.preEscapedText` etc. do not;
  `H.toHtml`/`H.toMarkup` (text, numbers shown as Haskell, `True`/`False`). Attribute values:
  string literal (escaped), `H.textValue`/`H.stringValue`/`H.lazyTextValue`/`H.toValue`,
  `H.preEscapedTextValue`/`H.preEscapedToValue`. `HA.for` exists (alias of `HA.for_`),
  `HA.class_`, `HA.type_`, `HA.data_`. `H.renderHtml(h)` → `string`.
* As in blaze, text inside `H.style`/`H.script` is escaped. The original therefore had broken
  rules in `standardHeader` (`font-family: &quot;Roboto&quot;` and the `.horizontal > *` /
  `.vertical > *` child rules are dropped by the browser) and an escaped `arrowDialogPrelude`
  script; this is reproduced, not fixed. Use `H.preEscapedText` for raw CSS/JS.

## StyleSheets (Clay)

* `Css` is the list of rules the Clay `do` block builds: `{ selector, properties: [key, value][] }`
  with selectors and values already in Clay's rendered text. `stylesheetInternal(css)` renders it
  exactly as clay-0.13.3 `renderWith pretty []` does (aligned colons, blank lines, banner,
  `#rrggbb` colours, `1.0s` times, `-webkit-`/`-moz-`/`-ms-`/`-o-` copies of `animation`,
  `::after`), then escapes it into `H.style` as blaze does. `webitStdCss`, `standardHeader` as in
  Haskell.

## Known gaps / faithful oddities

* As in Haskell, an event that cannot be decoded or names an unknown webit throws in the command
  pipe thread of `makeElmerEnv`, which then dies (the GUI stops responding), e.g. an event that
  reaches the routes after its webit was deleted, or a value no channel of the webit accepts.
* `deleteWebit` finalises the deleted webit twice (once directly, once as part of its tree), as
  in Haskell.
* No toolkit (`src/lib/GI`) changes.
