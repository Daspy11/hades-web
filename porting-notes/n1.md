## Model.GI.Notebooks

* `DiagramExport = readonly [Cairo.Render<void>, BoundBox]`.
* `ActiveEntity<P, V>` record (all Haskell fields; `activeEntityRefresh: () => void`,
  `activeEntityUpdates: B.Event<ModelScriptAct<P, V, V, Maybe<string>>[]>`,
  `activeEntityZoom: B.Behavior<Scale>`, `activeEntityExport: B.Behavior<Maybe<DiagramExport>>`,
  `activeWrapper: EntityWrapper<HadesRender, V>`), constructor `ActiveEntity(...)`.
* `BookManager<P, V>` record: `bookManagerDisplay: IORef<Maybe<Gtk.Widget>>`,
  `bookManagerContents: IORef<readonly ActiveEntity[]>`, `bookManagerActiveEvent`,
  `bookManagerActiveHandler: B.Handler<ActiveEntity>`, `bookManagerModelUpdate`,
  `bookManagerModelHandler` (also writes `bookManagerContents`), `bookManagerZoom: Event<Scale>`,
  `bookManagerRefresh: Event<null>`.
* `newBookManager<P, V>(scaleE, refreshE): [Gtk.Widget, BookManager]` (MomentIO, synchronous).
  `allBooks(manager): Gtk.Notebook[]` (synchronous). `sameWidget` is re-exported.
* Internal in Haskell, exported for tests: `hadesGroup`, `splitBook(handler, book, manager)`,
  `mergeBook(handler, book, manager)`, `newHadesBook(handler, manager)`.
* ModelDiagrams (`openDiagramInBook`) should do what the Haskell does: `notebookAppendPageMenu`
  + `notebookSetTabDetachable(book, page, true)`. Detachable tabs can then be dragged (HTML5
  DnD on the tab strip, Radix Tabs kept) to another notebook of the group and, as in GTK,
  dropped back on their own tab strip to reorder them (Alt+arrows reorder only *reorderable*
  tabs, which HADES never sets).

## Model.GI.PackageTree

* Dictionary first, then context/arguments:
  `entityToGtk(cls, picF, ent)`, `updateGtkTree(cls, parent, info, logs)`,
  `replaceGtkTree(cls, info, model)`,
  `modelWidget(cls: Editable<P, V> & EntityClass<V>, picF, modelInit, modelC: Changes<Model<V>>, selectB)`
  → `[GtkTreeInfo<V>, B.Event<S.Set<ModelId>>, B.Event<ModelScriptAct<P, V, V, Maybe<string>>>]`,
  `modelDragAndDrop(cls, info, vw, modelRef)` (exported, internal in Haskell),
  `processModelUpdates(cls, info, updates: Event<ModelUpdate<V, Maybe<string>>>, blats: Event<Model<V>>)`
  → `Event<Model<V>>`, `modelErrorWarningOn(parent, errE)`.
* `modelErrorWarning(parent, err): Promise<void>` (the `errorBox` Promise). Synchronous callers
  (tree updates, reactimate handlers) use `void modelErrorWarning(...)`: the box is shown
  without blocking, so later updates in the same batch are applied before it is closed.
* ModelEdit functions: `goToTreePath(ctx, path)`, `currentTreePath(ctx): number[]`.
  `ModelPath = readonly number[]`; `getSelectedRows(sel): S.Set<ModelPath>`.
* `GtkEntity(gtkName, gtkIcon, gtkId)` record (structural Eq/Ord; `show_GtkEntity`).
  `GtkTreeInfo<V>` is positional: `{ _0: TreeStore, _1: TreeModelSort, _2: TreeView, _3: StockFunc<V> }`,
  built with `GtkTreeInfo(store, sorted, vw, picF)`. `StockFunc<V> = (e: Entity<V>) => string`.
* Store helpers keep their gi-gtk shapes: `entityColumnTypes`, `entityToTreeRow(e): GValue[]`,
  `treeRowToEntity(row)`, `clearTree(store, name): TreeIter`, `storeEntity`, `storeEntityTree`,
  `storeEntityForest`, `getEntity(model, iter)`, `getEntityTree`, `getEntityForest`,
  `treeSortF(model, it1, it2): number`, `dragTargets(): Gtk.TargetEntry[]`,
  `treeIterFromPath(info, path): Maybe<TreeIter>` (exported, internal in Haskell).
* `HistoryItem(undoValue, undoText)` record; `ModelUpdate` type re-exported.
* `Model.Abstract.PackageTree.sequenceEvents` is specialised to `ModelEdit` actions in its TS
  port; `modelWidget` therefore has a local `sequenceEvents` over `ModelScriptAct`s (generators,
  sequenced with `yield*`). Script values from the widget never yield instructions themselves
  (they are `lift $ do ...`) except those produced by `Editable` (activation, menus).
* Faithful quirks: after a `ModelAdd`, `updateGtkTree` expands the new row using its path in
  the *unsorted* store (as the original), so the wrong ancestor may be expanded once the store
  order differs from the sorted order; `replaceGtkTree` warns (error box) for every expanded or
  selected entity missing from the new model; the Delete message says "Deleleted N entities".

## Toolkit changes

* `Reactive/Banana.ts`: `export type Handler<A> = (a: A) => void` (Frameworks `Handler`).
* `Gdk.ts`: `dragStatus(ctx, action | action[] | null, t)` now records `ctx.status` and sets the
  DOM `dropEffect` (`"none"` for `[]`/`null`); `DragContext` gained `status` and `event` (the
  current DOM drag event).
* `RenderTree.tsx`: tree rows are `display: contents`, which Chromium cannot drag — the cells
  are now the `draggable` elements (tree view DnD did not start at all before). Drag signals get
  widget coordinates (was bin-window coordinates, so handlers that convert, as GTK code does,
  subtracted the header twice); the default drop highlight is skipped when a `drag-motion`
  handler refused the drop with `dragStatus`.
* `TreeModel.ts` `TreeModelSort`: rebuilds present each sibling list in its previous sorted
  order before sorting, so re-sorting after a small change costs ~n comparisons instead of
  n log n (same result). Matters for `treeSortF` (natural order is ~25 µs per comparison).
* `Render.tsx` notebook: a detachable tab may be dropped back on its own tab strip (reorders it,
  as GTK's `do_detach_tab`); the pages area clips its content (`overflow: hidden`); a scrollable
  notebook keeps the current tab scrolled into view.
* `README.md`: DnD coordinate/refusal notes.

## Tests

* `Model/GI/PackageTree.test.ts` drives `modelWidget` under jsdom: selection both ways, in-place
  rename, activation, Delete key, right-click menu and drag-move (with a fake row DOM and
  `document.elementFromPoint` stub so `treeViewGetPathAtPos` works), `replaceGtkTree` keeping
  expansion/selection, duplicate `ModelAdd`, root deletion, out-of-step warnings. `errorBox` is
  mocked with `vi.mock` to capture the messages.
* `Test/GI/PackageTree.test.ts` `runTests` runs 1000 QuickCheck-style cases as in Haskell
  (~20–35 s; most of it is model generation).

## Known gaps

* `naturalOrder` (Text.NaturalOrder) costs ~25 µs per comparison; it is used by `Name`'s `Ord`
  everywhere (model maps) and by the tree sort. Memoising `chunkText` would help.
* GTK auto-expands a collapsed row hovered during a drag; the toolkit does not.
